# Definition of Done（既定）

すべての変更に毎回同じ基準で適用する「完了の定義」。タスクごとの **受け入れ条件**（design.md）が「正しいものを作ったか」を問うのに対し、DoD は「完了と言える品質か」を問う。両方を満たして初めて完了。
リポジトリに独自の DoD（`docs/definition-of-done.md`、CONTRIBUTING のチェックリスト、`.claude/go-workflow.json` の `dod`）があればそちらを優先する。

## 正しさ
- [ ] design.md の受け入れ条件をすべて満たす
- [ ] 実行時に確認済み（コンパイルが通るだけでなく、テスト・E2E・手元実行で振る舞いを確認）
- [ ] 新しい振る舞いに、変更がないと失敗し変更があると通るテストがある
- [ ] 既存テストがすべて通る（`go test -race`）
- [ ] 異常系・境界値が扱われている

## 品質
- [ ] format / vet / lint / modernize が PASS（SKIP・ENV は理由を明記）
- [ ] 理由のない `//nolint`、デバッグ出力、コメントアウトされたコード、TODO の放置がない
- [ ] 変更がタスクのスコープ内（無関係なリファクタを含まない）
- [ ] 実装レビューで CONFIRMED の Critical / High が 0 件

## 統合
- [ ] DB マイグレーション・設定・環境変数・feature flag の追加が反映され、手順が書かれている
- [ ] 公開 API・JSON・DB スキーマの後方互換を確認した（破壊的変更は明記）
- [ ] 生成コードが最新（生成元と一致）

## ドキュメント
- [ ] 公開識別子に doc コメント
- [ ] README / API ドキュメント / CHANGELOG の更新要否を確認した
- [ ] 残すべき設計判断は ADR 等に記録した（リポジトリに ADR の運用がある場合）

## リリース準備
- [ ] セキュリティレビューが PASS（govulncheck を含む）
- [ ] 新しい重要経路にログ・メトリクス・トレースがある
- [ ] ロールバック方法が明確
- [ ] 人間（ユーザー）がマージ前にレビューする前提で PR を作る
